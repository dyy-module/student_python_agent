## Q1(当日·概念对比)requests vs axios 的错误处理
1. axios 收到 4xx/5xx 会自动 reject 进 catch;requests 收到 404 时 `r.status_code` 拿到后,程序会抛异常吗?要让它抛该调什么方法?
2. requests.get 不加 timeout 会有什么风险?JS 的 fetch 默认又是怎样(对照 AbortController)?

- 我的回答:
- requests 拿到404后不会抛异常，需要手动调r.raise_for_status()
- 风险：1.调用线程被永久“钉住”2. 线程池/协程池耗尽，引发级联故障3. 文件描述符泄漏4. 日志沉默，故障排查困难
- JavaScript fetch：默认行为与 AbortController 的对照
    fetch 的规范中没有 timeout 选项。一个 fetch 请求会一直运行，直到服务器响应或网络错误关闭连接。
    不过，运行环境可能施加非规范的后台限制。例如，Chrome 可能在约 300 秒后终止挂起的连接，Node.js 的 undici 对响应头和响应体静默也设有 300 秒的固定计时器。但这些是兜底机制，不是你可以依赖或配置的业务超时

    AbortController / AbortSignal 的作用 设计为通过 signal 接受外部取消指令.
    方式一：手动组合 AbortController + setTimeout
    ```javascript
    const controller = new AbortController();
    const timeoutId = setTimeout(() => controller.abort(), 5000);

    try {
    const response = await fetch(url, { signal: controller.signal });
    // ...
    } catch (err) {
        if (err.name === 'AbortError') {
            // 请求被中止（可能是超时，也可能是用户手动取消）
        }
    } finally {
        clearTimeout(timeoutId); // 请求在超时前完成，清除定时器
    }
    ```

    方式二：使用 AbortSignal.timeout()

    ```javascript
    try {
        const response = await fetch(url, {
            signal: AbortSignal.timeout(5000) // 5 秒后自动中止
        });
    } catch (err) {
        if (err.name === 'TimeoutError') {
            // 明确是超时导致的失败
        } else if (err.name === 'AbortError') {
            // 其他原因的中止（如用户导航离开）
        }
    }
    ```



## Q2(当日·阅读说输出)try/except 结构体
下面对一个"必然连不上"的地址运行,请说出打印顺序与是否崩溃(注意 else 与 finally):

```python
import requests
try:
    r = requests.get("http://不存在.local", timeout=2)
except requests.exceptions.RequestException as e:
    print("网络错")
else:
    print("状态", r.status_code)
finally:
    print("结束")
```

- 我的回答:
- 不会崩溃，会打印 "网络错"，然后打印"结束"
- 因为RequestException 是所有http 错误的基类，会拦截所有 请求错误
