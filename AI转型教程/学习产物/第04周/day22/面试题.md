# 参考答案(2026-10-28 闭卷作答与评分后整理,已改用大白话版,仅供复习)

## Q1 参考答案
**1.1 激活改了什么**
- 一句话:activate 就是把 `.venv\Scripts` 这个文件夹加到当前终端窗口的"找程序顺序"(环境变量 PATH)的最前面。之后你输 `python` 或 `pip`,系统按这个顺序先找谁就命中谁——于是用的是虚拟环境里的 Python,装包、导包也都走 .venv 里那份。
- 不激活直接 `import requests`:这时你用的 `python` 是系统全局装的那个,它那里没装 requests,所以报 ModuleNotFoundError(这种错属于 ImportError 的一种)。env_check 里 `except ImportError` 接住的就是它。
- 面试官常追问的一点:激活只决定"终端输 `python` 时找到哪个 Python",对已经被指定路径的那个 Python 没有任何影响——不激活时直接用完整路径跑 `.\Scripts\python.exe`,import requests 一样成功(验收时就是这么跑的)。因为那个 Python 自己就知道去虚拟环境里找包,不需要 PATH 帮忙。

**1.2 为什么 requirements.txt 写"包名==版本"锁死,而不像 package.json 写 `^1.2.3` 这种范围**
- 对应关系:requirements.txt 相当于 npm 的 package-lock.json(记录每个包最终确定的版本号),而不是 package.json 里的 dependencies(只写一个允许的范围)。证据:我们的文件里有 certifi、idna、urllib3 四个从没自己装过的包——它们是 requests 依赖的下游包,pip freeze 把所有层级的包全都展开、版本写死。
- 原因:npm 敢在 package.json 里写范围,是因为还有第二个文件(lock)保管着"上次实际装出来的具体版本";pip 只有 requirements.txt 这一个文件。如果这里也写范围,那今天装和三个月后装,装出来的版本可能不一样,环境就悄悄变了。所以只能把"实际验证过的那一套版本"直接写进去,双等号就是写死版本的最直接办法。
- 后续:第13周学的 uv/Poetry 会把"第二个文件"这层机制加回来,到时候就不必这么无奈了。

## Q2 参考答案
**2.1 该写 `except ImportError:`还是 `except Exception:`**
- 应该写 `except ImportError:`。写得太宽有两个坏处:一是进了兜底就分不清到底哪里错了、没法针对性处理;二是会把不相干的错也接住。真实例子就发生在 day22:extra 里 print 打印时自己报了一个 UnicodeEncodeError(输出编码错),因为它恰好是 ValueError 的一种,被 `except (FileNotFoundError, ValueError)` 接住了——程序看着没事、正常退出,实际问题被盖住了。
- 配套原则:只接自己知道怎么处理的错;不会处理的就让它当场崩掉,崩在眼前比带着病继续跑好排查。写好几个 except 时,窄的写在前、宽的写在后;顺序反了的话宽的先把所有错都截走,窄的那几行永远轮不到执行。

**2.2 ImportError 的继承关系,能不能被 except Exception 接住**
- 能。继承关系是:ImportError 是 Exception 的子类,Exception 又是 BaseException 的子类,所以 `except Exception` 接得住 ImportError。
- 反过来要记的两个特例:KeyboardInterrupt(按 Ctrl+C)和 SystemExit 属于 BaseException 但不属于 Exception——所以 `except Exception` 接不住按 Ctrl+C,这是 Python 故意留给用户的退出口。
- 容易混的一点:import 那一行代码本身语法写错,报的是 SyntaxError(语法都没通过,根本执行不到导入那一步);ImportError 专指"尝试导入了,但找不到这个包"。

## Q3 参考答案
**3.1 为什么先 strip() 再 split("==")?不 strip 会得到什么脏结果?**
- 逐行读文件时,每一行末尾都自带一个换行符 `\n`。不去掉它有三个后果(day22 全都真实遇到过):①print 打印完自己还要换一次行,两个换行叠一起,清单每行之间多一个空行;②split 拆出来的版本号尾巴带着 `\n`,拿它去比较、拼接或写回文件都会出错;③碰到空行或注释行(里面根本没有"==")时,split 拆不出两个值,直接报 ValueError——extra 里 except 那行防的就是这个。
- 补充一个:文件第一行开头可能藏着一个看不见的字符 `\ufeff`(叫 BOM,文件签名头)。strip() 去不掉它,因为 Python 不把它算作空白字符(第3轮实测过)。对付它的办法是读的时候用 encoding='utf-8-sig'——这个编码的含义就是"开头要是发现这种签名头就丢掉,没有也正常读"。

**3.2 用 with open 而不是裸 open 的好处**
- 先订正一个说法:with 关掉的是"文件句柄"(程序打开文件时系统发的一张"使用凭证"),不是"关闭进程"——进程是正在运行的程序本身。
- 三个好处:①不管 with 这一块代码里有没有出错,退出时都保证把文件关掉;裸 open 要自己记得关,一旦中途出错,关文件那行就跳过去了;②写文件时内容不是立刻存盘的,先攒在缓冲区里,"关闭"这个动作才会把攒的内容真正写进文件——没关就异常退出,数据会丢;③Windows 上文件没关就一直处于被占用状态,别的程序(甚至你自己)删不掉也改不了。另外:CPython 里句柄通常会在没人用时自动关,但那是这个版本的具体实现,不能当成指望。
