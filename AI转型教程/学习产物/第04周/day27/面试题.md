# 标准答案(2026-11-11 验收日下发)

## 一、标准答案要点

### Q1 分层与容错
- **Q1.1 为什么拆三层**:
①单一职责——每层只答一个问题(数据从哪来/怎么变干净/存到哪去),改一处不牵动其他层;
②可测试——清洗函数是纯函数(str 进 str 出),可单独喂样本断言,不必碰磁盘网络;
③可定位——报错栈直接指向层;④可复用——第07周 RAG"文档加载与清洗"就是同分层换个源。
**JS 类比**:等价 `fetch → transform → render` 三段或 `map/filter` 管道——来源、变换、渲染从不混在一个函数;层间靠约定形状传递(相当于组件 props/TS 接口),
typing 标注在本日产物里就是把层间契约显式写出来。
- **Q1.2 单文件失败为何不能崩整批 + try 放哪层**:
批处理价值在吞吐,坏文件崩掉整批=前面所有 I/O 算力全废,且重试还会在同一坏文件再崩;
工业做法是失败收集→降级→重试队列。
try/except 放 **for 里面**:作用域粒度=容错粒度,放外面一次异常直接跳出循环、整批终止,语义上等价"不容错";
放里面逐文件独立捕获、print 警告、continue 跳过,汇总还能区分成功/失败数。

### Q2 手写序列化 vs json
- **Q2.1 `import json` 能省掉哪部分**:json 的作用恰是**让你不再需要任何自定义规则**。省掉:
①写出侧手工拼接(f-string 逐字段拼+处理特殊字符);
②读回侧手工拆解(split 链/推导式)。
`json.dumps(obj)` 一个调用把嵌套结构转成规范化字符串、
`json.loads(s)` 原样还原,
**转义、嵌套、类型还原("1" vs 1、null vs None)全由它接管**。
一句话:json 是"协议",自定义 `key:value|` 只是"约定"。
- **Q2.2 自定义格式与取舍**（题干三问逐一答）:
①**什么格式**:一条多字段记录用两个分隔符分层——字段内 `key:value`、字段间 `|`,即 `key:value|key:value`;多条记录之间用换行,写一行=一条记录。
②**读回怎么拆回去**（两层 split,先拆行、再拆字段）:外层按换行切出每条记录,内层先按 `|` 切出各 `key:value` 对、再对每对按 `:` 切成键与值,组装成 dict;整批读回得到 list of dict(一行=一个 dict)。顺序不能反——先拆到“一条记录”粒度,再拆记录内字段。
③**取舍**:选 `:`/`|` 是因为正文里罕见,但清洗对象是 HTML/md 文本——`|` 是 md 表格原生字符、`:` 出现在链接与时间戳里,冲突风险真实存在;一旦字段值自带分隔符,读回就会错位。这正是无转义手写的天花板,也是 `import json` 存在的理由。

### Q3 re 去标签
- **Q3.1 `[^>]+` 匹配什么 / 为何不用 `.`**:
`[^>]` 是**取反字符类**——任何一个"不是 `>`"的字符,`+` 至少一个;整体=从 `<` 后一路吃到**最近的** `>` 前,锁住标签 body 不越界。
弃用 `.` 的真正理由:`.` 能吃掉任意字符**包括 `>`**,匹配失去上界,剩"第一个 `<` 到最后一个 `>`"式贪心,删标签会把两个标签之间正文一起吞;
另 `.` 默认**不匹配换行**(要 `re.S`),字符类 `[^>]` 对换行照吃,多行 HTML 里还有这层差异。

- **Q3.2 `a < b > c` 会怎样 / 什么局限**:模式从 a 后的 `<` 起匹配,`[^>]+` 吃掉 ` b `,遇 `>` 停下——**整段 ` < b > ` 被当标签删掉**,只剩 `a c`。
局限:**正则只认字符形状,没有语法/上下文概念**;再深一层——正则属正规式,天生**数不了嵌套层级**,HTML/XML/JSON 这类递归结构只能用真解析器("用正则解析 HTML 会被嘲笑"的机理)。
