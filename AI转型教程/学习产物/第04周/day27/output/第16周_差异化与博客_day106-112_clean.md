## Day106(周一,7h)· 差异化项目(1/3):Agent 执行可视化面板——架构设计与"规划"阶段

今天启动本周最容易被记住的作品——差异化项目「Agent 执行可视化面板」:把 Agent 的一次执行(规划→工具调用→观察→结果)做成可视化面板,让面试官"看得见"你的 Agent 在想什么、做什么、依据什么。今天先定架构与数据契约,并把"规划"阶段渲染出来。基础已在:周12 你学过 Agent 交互模式,周11 你做过工具调用可视化,今天做的是把它们拼成一块完整面板。

💡 前端开发者速读:Agent 执行可视化 ≈ 给一次 Agent 运行做"执行时间线"(类似你做过的请求瀑布图/DevTools Network 面板);四阶段 ≈ 一个状态机的四段,每段一张卡片;你 10 年 React 的组件拆分与状态管理直接迁移,难点只在事件数据模型设计,不在 UI。

### 学习内容

- 面板信息架构:一次 Agent 运行 = 一条执行记录,含四阶段(规划/工具调用/观察/结果)
- 执行事件数据模型设计(TS 类型:阶段/时间戳/载荷,联合类型按 phase 收窄)
- "规划"阶段可视化:展示 Agent 拆解出的步骤列表与顺序
- 组件分层:Timeline(时间线容器)/ PhaseCard(阶段卡片)/ StepList(步骤列表)
- 数据来源:后端把 Agent 执行事件以结构化 JSON 推给前端(流式,复用第10-12周)

### 讲解

结论先行:面板的本质是"事件流 → 时间线 UI"。不要一上来堆 UI,先把四阶段的数据契约写死——执行事件长什么样(阶段、时间戳、载荷),后端在 Agent 执行过程中结构化地吐事件,前端按 phase 分发渲染。UI 只是数据契约的投影;契约定清楚,day107/108 的扩展就是加卡片,而不是推翻重来。

```tsx
// 教学演示:执行事件数据模型与时间线骨架(教学演示,非产物答案)
type Phase = "plan" | "tool_call" | "observe" | "result";
type AgentEvent =
  | { phase: "plan"; steps: string[] }
  | { phase: "tool_call"; tool: string; args: Record }
  | { phase: "observe"; summary: string }
  | { phase: "result"; answer: string; citations: string[] };

function Timeline({ events }: { events: AgentEvent[] }) {
  return {events.map((e, i) => {e.phase})};
}
```

## Day107(周二,7h)· 差异化项目(2/3):工具调用与观察阶段可视化

昨天定了契约、跑通"规划"。今天做面板的核心看点——"工具调用"与"观察"两阶段:模型请求调用哪个工具、传了什么参数、工具返回了什么观察结果,全程在面板上可追溯。这是周11 ToolCallView 的升级:从单次 tool call 卡片,升级为四阶段时间线中可关联、可回看的一段。

💡 前端开发者速读:工具调用阶段 ≈ 你既有的"请求详情面板"(方法/参数/响应);观察阶段 ≈ 把工具返回做一次"摘要渲染"而非裸 JSON 倾倒;call→result 的 pending 状态机你闭眼能写;加一个亮点——把"模型为什么调这个工具"也渲染出来(入参即证据)。

### 学习内容

- 工具调用阶段可视化:工具名/入参/状态(调用中/已返回)的调用卡片
- 观察阶段可视化:工具结果的摘要渲染(结构化摘要,而非裸 JSON)
- call 与 observe 事件按 id 关联成对,串联进时间线并标注耗时
- 失败工具调用的可视化(错误态与可读原因,不崩溃)
- 后端事件推送:tool_call / observe 事件的结构化输出约定

### 讲解

结论先行:调用与观察两个阶段要"分开渲染、互相引用"——调用卡片展示"模型请求了什么"(工具名+入参),观察卡片展示"世界回了什么"(结果摘要),两者用同一事件 id 关联。失败不是异常而是正常事件:用错误态渲染并给出可读原因。面板的可信度,正来自它对失败的诚实展示——这也是面试时最有说服力的细节。

```tsx
// 教学演示:调用与观察卡片的关联渲染(教学演示,非产物答案)
function CallObservePair({ call, observe }: { call: AgentEvent; observe?: AgentEvent }) {
  return (
    
      🔧 {call.tool} · 入参 {JSON.stringify(call.args)}
      👁 观察:{observe ? observe.summary : "等待工具返回…"}
    
  );
}
```

## Day108(周三,7h)· 差异化项目(3/3):结果阶段可视化 + 面板整合联调(可运行演示)

今天收尾差异化项目:渲染"结果"阶段(最终答案 + 引用依据),把四阶段时间线整合联调,跑通端到端演示。验收标准不是"功能都有",而是"给面试官现场演示 3 分钟讲清一次 Agent 执行"——从提问到四阶段依次点亮。这也是"前端×LLM 交互层"差异化叙事核心实证的完成日。

💡 前端开发者速读:结果阶段 ≈ 终态卡片(答案 + 引用/依据链接),是你做过的"结果页 + 溯源链接"套路(呼应第08周引用标注);整合联调 ≈ 你熟悉的端到端自测;把面板录屏/GIF 嵌入 README ≈ 你给项目做 demo 展示的常规操作。

### 学习内容

- 结果阶段可视化:最终答案 + 引用依据(来源片段/工具输出编号)渲染
- 四阶段时间线整合:plan → tool_call → observe → result 全流程串联
- 端到端联调:真实后端 Agent + 面板,一次完整执行全程可见
