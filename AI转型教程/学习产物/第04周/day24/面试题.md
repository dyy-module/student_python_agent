## Q1(当日·概念对比)findall vs search vs match
1. 三者返回值分别是什么类型?没匹配到时各自返回什么(findall 空 vs search 无匹配)?
2. 为什么"提取全部邮箱"用 findall、"判断手机号开头"用 match、"全文找第一个"用 search,而不是随便互换?

- 我的回答:
    re.match(p, s)	re.search(p, s)	re.findall(p, s)
    匹配成功	Match 对象	Match 对象	列表
    没匹配到	None	None	[](空列表,永不为 None)
    匹配位置	仅从字符串开头(位置 0)	全文任意位置	全文所有位置
    结果数量	至多 1 个	至多 1 个(第一个)	全部

    Match 对象是"富信息"的:要用 .group() 取内容、.span() 取位置;直接 m.group() 前必须判空,否则 AttributeError(新手最常踩的坑)。Match 对象存在即为真,所以 if m: 是标准写法。
    findall 永远返回列表,空列表为假,所以 if re.findall(...) 也能当存在性判断——但拿不到位置信息。
    findall 遇到分组的坑:无分组返回整段匹配的字符串;1 个分组返回该分组内容的列表;≥2 个分组返回元组列表。只想分组不想改变返回结构,用非捕获分组 (?:...)。

    邮箱可能出现在文中任意位置、可能有任意多个,还要求"拿到所有内容"。findall 一次返回全部。
    判断手机号开头，所以用match 匹配开头
    全文找第一个，含有的意思。所以用search 

## Q2(当日·为什么)原始字符串 r""
写正则 `r"\d{3}"` 与 `"\d{3}"` 结果一样,但教程要求加 r。
1. 不加 r 时反斜杠会在 Python 字符串层发生什么(结合 day1 学过的转义)?
2. 哪条正则里"加了 r 反而错"几乎不存在、但"漏了 r 容易错"?举一个 `\b` 或 `\d` 的例子说明。

- 我的回答:
1. 正则要串行过两道解释器
    源代码字面量 ──① Python字符串层 ──> 内存中的字符串 ──② re引擎 ──> 匹配行为
    r 前缀的作用 = 让第①层不干活(原样照抄)，把解释权全部留给第②层。
    "\d{3}"：
    - Python 看到 \d,查转义表——查无此项
    - 规则是：无法识别的转义序列原样保留，但从 Python 3.6 起发警告，3.12 起默认显示 SyntaxWarning: invalid escape sequence '\d',官方计划未来升级为 SyntaxError
    - 于是正则引擎收到的仍是 \d{3}——碰巧正确
    所以“结果一样”的本质：靠的是 Python 对非法转义的宽容放行，不是设计保证。一旦撞上 Python 认识的转义，反斜杠序列会在第①层被“截胡”改写
2. 
   raw string 不是“消灭转义”，而是“把解释推迟给正则引擎”。而 re 引擎自己也认识 \n \t \x41 这类通用转义，再加上自己的一套 \d \b \s \1。两个解释器在这些序列上语义兼容，所以“全部交给正则层”几乎总是你想要的。(唯二的例外：r-string 不能以奇数个反斜杠结尾，r"C:\" 直接语法错误；以及极少数想让 Python 先处理的动态拼接场景。)

   漏 r 容易错——Python 层抢跑，而且对部分序列的“翻译”与正则语义完全不同：信息在正则引擎看到之前就被破坏了，还是静默失败——不抛异常，只是结果为空或不对。



## Q3(往期复习·day23 requests + 本日 re 组合)阅读说输出
下面跑通后 print 什么(注意 findall 在有/无匹配时的返回)?

```python
import re
s = "价格100元,编号abc"
print(re.findall(r"\d+", s))
print(re.findall(r"\d+", "无数字"))
m = re.search(r"编号(\w+)", s)
print(m.group(1) if m else "没找到")
```

- 我的回答:
[100] # findall,返回数组
[] # findall 找不到返回空数组
'abc' # 有一个分组时，返回的是分组内容
