## Q1(当日·"为什么")必须 asyncio.run 点火
JS 里直接调用 async 函数就开始跑,Python 调 `main()` 却什么都不发生,必须 `asyncio.run(main())`。
1. 为什么?直接调用协程函数返回的是什么对象、不 await/run 它为何不执行?
2. 在协程里误用阻塞的 `time.sleep(2)` 而非 `await asyncio.sleep(2)`,事件循环会发生什么?

- 我的回答:
1. JS 的 Promise 是“运行时自动调度”的，而 Python 的协程是“惰性对象”，必须显式交给事件循环才会执行
    |----|JavaScript|Python|
    |----|----|----|
    |调用 async 函数	|立即创建 Promise 并开始执行|	仅返回 coroutine 对象，不执行
    |事件循环|	浏览器/Node 内置，永远在跑	|asyncio 可选，需 asyncio.run() 手动启动
    |并发单元|	Promise/Task 自动注册到事件循环| 必须用 create_task() 或 gather() 显式注册

    为什么会这样？
    JS 天生单线程 + 内置事件循环
    Python 是通用语言，默认同步执行
2. 会阻塞时间循环，等待2秒 再执行. time.sleep是同步的

# 标准答案(2026-11-07)

## Q1 标准答案
1. 调用 Python 协程函数只会**返回一个 coroutine 对象**,它是一棵"待执行的暂停说明书",不会被任何机制自动调度;只有 **await 它**(或在协程内 await、或交给 `asyncio.run` 启动的事件循环逐步驱动)才会真正执行。JS 则不同:调用 `async function` 返回 Promise 并**立即开始执行**(跑到函数内第一个 await 前都是同步执行),由运行时内建的事件循环自动调度。所以 Python 必须 `asyncio.run(main())` 手动点火;而 `await` 只能出现在 `async def` 内,顶层想跑协程也只能走 `asyncio.run`。另注:"Promise 是运行时自动调度"说法基本成立,但精确表述是 Promise **eager**——创建即执行到首个 await,并非全部交给循环排队。
2. `time.sleep(2)` 是同步阻塞调用,它**不让出控制权**,直接霸占运行事件循环的那唯一线程 → **整个事件循环冻结 2 秒**:期间任何其它协程都无法被调度,连"开始"这类 print 都发不出去,所有"等待中的"任务集体卡住。异步彻底退化,甚至比同步分批执行更糟(没有任何并发收益还占用循环)。正确姿势是 `await asyncio.sleep(2)`:在等待点把控制权让渡给事件循环,循环得以切去跑其它协程,2 秒后再恢复本协程——这正是"协程 = 可暂停/恢复的函数"中 await 作为暂停点的含义。

## Q2 标准答案
1. 总耗时约 **3 秒**(顺序 await,A 等满 1 秒完成后才轮到 B 等 2 秒)。实测输出顺序(已本机跑通核验):
   ```text
   start A      ← 立即打印
   start B      ← 约 1 秒后(A 完成才调用 B)
   A B          ← 约再过 2 秒(共 3 秒)打印 a、b 两个返回值
   ```
   注意末行是 `print(a, b)` 打印返回值,两个 start 之间隔 1 秒、而非各自都拖 1 秒。
2. 这是**串行**(每个 await 都等前一个彻底完成)。改并发用 **`asyncio.gather`**:
   ```python
   a, b = await asyncio.gather(t("A", 1), t("B", 2))
   ```
   两个协程同时点火,总耗时取最长者约 **2 秒**。gather/create_task 属【超前】,本周仅识别,说法正确即可。

## Q3 标准答案
**不能。**`asyncio.gather` / `create_task` 只能调度**可等待对象**;`requests.get(...)` 是同步阻塞函数,调用它的那行代码会把事件循环线程整个卡住(与 Q1-2 的 `time.sleep` 同一性质)。因此即使把 10 次 requests 调用"包成任务再 gather",阻塞仍发生在循环线程上:轻则任务原地串行执行、循环期间全部冻结,重则根本跑不出并发收益——10 个 URL 依旧约 10 倍单次耗时。原因一句话:**async 壳子无法消除同步内核的阻塞**。真异步并发抓取需要 **aiohttp 或 httpx** 这类原生异步 HTTP 客户端(【超前】,第05/13周会用到),它们从发起 IO 那一层就非阻塞,能与事件循环配合在等待期切跑其它请求。(补充常识:线程池方案如 `asyncio.to_thread` 可"绕开"阻塞,但那是多线程包装、真异步不在此列,均属【超前】不要求。)
