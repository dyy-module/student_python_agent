## Q1(当日新知·"为什么") 开了 JSON Mode,为什么还要用 try/except 兜 json.loads?JSON Mode 保证的是"合法 JSON"还是"字段符合预期"?两者区别是什么?
考点:response_format 的作用边界(强制合法 JSON,不保证 schema);字段仍需自校验;我的回答:
1.为什么还需要 try/except。因为大模型的回答具有随机性，虽然约定为json,但大模型仍有可能不乱输出。
如果一次输出有问题，就会造成程序崩溃，所以需要 try/except
2.json mode 只是保证json格式合法，不保证字段符合预期。
3.大模型可能会加额外字段，可能会编造数据。区别 前者只保证是json结构。后者需要保证 数据符合预期。

## Q2(当日新知·概念对比) `json.loads` 与 `json.dumps` 分别把什么转成什么?它对应 JS 里的哪两个方法?模型返回的 content 属于哪种、需要哪个转换?
考点:序列化/反序列化方向;与 JSON.parse/JSON.stringify 的映射;我的回答:
1.json.loads 把符合json规范的str 转换为dict,dumps则是把符合json 的dict转为 json string
2.对应js里的 Json.parse 对应JSON.loads , JSON.stringify 对应json.dumps
3.大模型返回的都是str,需要json.loads 转换成dict,方便程序使用。大模型也可能返回错误信息 和空数据，需要做兜底处理

## 参考要点(助教补录 2026-11-28·第2版)｜总分 11/15

### Q1｜得分 4/5
- 边界答对：json_object 只保证「合法 JSON」，不保证字段名/类型/取值符合预期，字段仍需自校验。
- 失败归因需补正：不是「模型随机不听话」这么简单。确定性失败源有三：①max_tokens 截断——OpenAI 官方明确「即使 Structured Outputs，生成达到 max_tokens 或其他停止条件时仍可能不符合 schema」；②空 content——DeepSeek 官方：输出无法识别为 JSON 时，非 JSON 内容被替换为空格(U+0020)，finish_reason 仍可能是 stop；③传输/服务端异常。所以 try/except 永远必要。
- ⚠ 上一版助教把「约束解码」安到 json_object 上是错的，已订正：constrained decoding(Schema→CFG→逐 token mask)是 OpenAI 公布用于 Structured Outputs(json_schema + strict:true) 的机制；json_object 官方措辞只是「improves reliability for generating valid JSON」，实现手段未公布。DeepSeek/百炼文档也都只承诺「输出合法 JSON」，未提约束解码。
- 你 index.md 写的「json_object：保证合法，json.loads 基本必过」是合适的工程口径；但「json_schema 100% 保证」要加前提：未触发 refusal 且未被 max_tokens 截断。
- 来源(均 2026-11-28 抓正文核验)：OpenAI《Introducing Structured Outputs in the API》2024-08-06 https://openai.com/index/introducing-structured-outputs-in-the-api/ ；DeepSeek JSON Output https://api-docs.deepseek.com/zh-cn/guides/json_mode ；百炼 Chat 参数页 https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions

### Q2｜得分 4/5
- 方向已答对(你自己订正了)：json.loads = str → dict；json.dumps = dict → str。✓
- 仅剩拼写：JS 侧是 JSON.parse / JSON.stringify(大写 JSON，stringify 不是 stringfy)。面试白板写错方法名会扣印象分。
- 记忆锚：loads = load string；dumps = dump string。带 s 的那个处理的是 str。
- content 是 str → json.loads；落盘/存档 → json.dumps(ensure_ascii=False 保中文)。
- 你第3点主动补了「错误信息与空数据需兜底」，超出题面要求，属加分项。

### Q3｜得分 3/5
- dict.get + 默认值只解决「缺 key 不崩」，没解题设的「key 名漂移」：score 变 sentiment_score 时，get("score", 0) 静默返回 0，真实分数丢了。
- 完整思路：①多候选 key 依次尝试(score → sentiment_score → confidence)，取第一个命中的；②用 in 判存在性，全没命中时打印提示 + 保留原始返回便于排查，而不是静默填默认值；③区分「模型没给」与「给了空值」——默认值会把前者伪装成后者(你产物里刚修的就是这个点)。
- 治本：prompt 里字段名写死 + 给 JSON 样例(样例即契约)，降低漂移概率；要彻底锁死字段名/类型，用 json_schema。
