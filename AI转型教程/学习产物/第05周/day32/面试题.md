## Q1(当日新知·"为什么") few-shot 示例对为什么 effective?它是在"训练"模型吗?模型到底在利用示例的什么信息?
考点:上下文学习(in-context learning)的机制——不是梯度更新,而是模式模仿;我的回答:
1. LLM本质是预测下一个可能性最高的token,所以给出的示例token,能有效的帮助命中相似的token
2. 不是在训练模型，LLM产出模型训练就结束了。投入语料，只是在帮助模型输出，并不会改变模型向量权重
3. 模仿示例的模式

## Q2(往期复习·day31 易错) 多轮对话里,为什么必须把模型的 assistant 回复也 append 回 messages?如果每轮只 append user 消息,会发生什么?
考点:大模型无状态、上下文完全由携带的 messages 决定(day31);我的回答:
1. 本质原因是大模型没有记忆，每次输入都是一次新的预测。所以需要把之前的记录作为上下文重新输入大模型，以形成前后连贯的回答。
2. 每轮只 append user，会丢失之前的回答，每次重新回答所有问题。并且因为LLM不可重复性，每次答案都不一样。

## Q3(往期复习·代码) 你封装了 def ask(messages) 来复用请求。如果 ask 里需要同时支持"裸 prompt"和"有技巧 prompt"两种模式,你会怎么设计参数而不复制整个函数体?(只说设计思路,不写完整代码)

ask 只做接受消息体，不对消息体做任何更改，不区分"裸 prompt"和"有技巧 prompt"两

## 标准答案(2026-11-28 闭卷作答并对答案后补录)

### Q1

不是训练。推理阶段模型权重是冻结的,示例不进入任何梯度更新、不改变任何参数;换一个会话,模型对这批示例的记忆为零。

真实机制是**上下文学习(in-context learning)**:示例作为条件上下文塞进 prompt,改变的是**给定这段上下文后的 next-token 条件概率分布**——模型从中识别出任务模式(输入→输出的映射、标签空间、输出格式、语气),再对新输入复现同一模式。

示例携带四类信息:
1. 任务定义:什么输入该得到什么输出(最核心);
2. 输出格式与标签集合:只许答 positive/negative、必须 JSON、不超过多少字;
3. 风格与粒度:语气、详略、人称;
4. 边界:哪类写法算正例、哪类算负例(靠示例的对比来划)。

为什么模型肯照做:预训练见过海量"按上文模式续写"的文本,指令微调又专门强化了"把示例当规范遵守"。可以理解为——示例是用数据写的一段隐式程序,把原本含糊的任务规格显式化。

两个引申结论:示例标签写错会带偏输出(模型忠实模仿错误);示例不是越多越好,与任务不匹配的示例和 token 成本都会反噬。所以关键在"同分布、标注正确、格式一致",不在数量。

### Q2

大模型本身无状态,记忆全部由调用方应用维护:messages 列表就是唯一的记忆载体,每轮整体发上去。

每轮必须 append assistant 回复的原因与漏掉的具体后果:
1. 模型看不到自己上一轮说了什么,接不住指代式/省略式追问("那元组呢""再短一点"),只能把追问当成新问题重解,表现为重复作答、答非所问或前后自相矛盾;
2. messages 结构退化成连续多条 user,语义从"对话轮次"变成"多段并列输入",模型无从判断哪条是问题、哪条是补充;
3. 上一轮回复往往是信息量最大的一段上下文,丢掉它等于每轮都从零开始理解。

补充精确口径:并非"每次重新回答所有问题"那么整齐,崩坏程度取决于问题对前文的依赖强度——依赖越强掉得越明显。相关正面写法是 append assistant 到 messages 后再 append 新的 user(day31 multi_turn_chat.py 即此结构)。

### Q3

题目问接口设计,不要求实现。两个可接受方案:

**方案A(职责拆分,推荐)**:`ask(messages)` 只负责"发一次请求 + 异常兜底 + 返回 content 字符串",完全不感知 prompt 技巧;另设拼装函数 `build_messages(task, system=None, examples=None)` 负责拼 system 与示例对,调用方决定传不传。

**方案B(单函数可选参数)**:`def ask(prompt, system=None, examples=None, model=..., temperature=...)`,内部 `if system:` 拼 system、`if examples:` 拼示例对,最后统一追加 user 消息。

必须说到的两个技术点:
1. **默认参数写 `None`,绝不写 `[]`**——可变默认参数只在函数定义时求值一次,多次调用共享同一个 list,示例会越拼越多;判断用 `if system is not None`,不能写 `if system`(空字符串是合法输入)。
2. 函数体只有一份:两种模式的差异完全由"传不传参数"或"调用哪个拼装函数"表达,异常兜底与取 content 只写一处。

打分口径:答出"参数化而非复制函数体"+"两种模式共用一份函数体"即及格;指出"关注点分离,ask 不负责拼 prompt"是加分项,但须同时给出参数形态或拼装函数名——只答"ask 不区分模式"等于回避题眼。
