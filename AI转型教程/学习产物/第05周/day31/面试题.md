## Q1(当日新知·"为什么") 大模型本身是"无状态"的,那多轮对话的"记忆"到底是谁实现的、怎么实现?为什么每轮都要把 assistant 的回复也 append 回 messages?
考点:messages 完整历史累积机制;漏 append assistant 会怎样;我的回答:
怎么实现：通过把每轮和之前的信息再次输入大模型实现的
记忆谁实现：自定义的 agent 程序
为什么append 每轮 assistant 的回复：因为大模型没有状态，所以它不知道之前说了什么，只有把结论也带入，才有连贯性 

## Q2(往期复习·day30·易错) os.environ.get("XXX_API_KEY") 与 os.environ["XXX_API_KEY"] 在 key 缺失时行为有什么不同?为什么教程推荐前者配合"缺失优雅退出"?
考点:环境变量两种取法的异常行为差异(day30 往期复习);与零硬编码安全规范的关系;我的回答:
os.environ.get("XXX_API_KEY") 在key缺失是返回None,可以设置默认值 os.environ.get("XXX_API_KEY",'1')
os.environ["XXX_API_KEY"] 无key时会直接抛出错误 keyError
environ.get 是安全的，不会因为找不到key 意外报错导致程序崩溃，所以推荐os.environ.get

## Q3(往期复习·第03周异常+第01周控制流·机制) 要做到"单轮调用失败不导致整个程序崩溃",try/except 应该包住整个 while 循环,还是只包每轮内部的调用部分?两种放法行为上有什么区别?
考点:异常捕获范围与循环控制流的配合(往期复习);可结合 day31 多轮对话场景说明;我的回答:
只包每轮的内部调用。
区别：
包住每轮调用，颗粒度更细，知道是哪轮报错了，报的什么错，程序不会崩溃，还能继续处理
包住while,无法分辨是调用出错了 还是其他程序出错了，导致错误难以定位

## 标准答案(2026-11-20 闭卷作答并对答案后补录)

### Q1
多轮对话的"记忆"由**调用方应用(客户端程序)**实现,模型本身无状态。机制:每次请求都把完整 messages 历史(system 首条 + 历次 user + 历次 assistant)整体发给模型,模型据此"看到"前文。每轮必须把 assistant 回复也 append 回 messages,因为模型不保存自己上一轮说过什么;漏回传则上下文断裂——模型可能重复、自相矛盾,或接不上指代式追问(如"那元组呢")。

### Q2
- `os.environ.get("KEY")`:键缺失返回 None(可传第二参作默认值),不抛异常。
- `os.environ["KEY"]`:键缺失抛 **KeyError**。os.environ 是类字典映射,取不存在的键 → KeyError;NameError 则是引用未定义的变量名,二者机制不同。
- 推荐 get 配合优雅退出:把"缺失"转为可判断的 None,由程序主动提示并 `raise SystemExit` 干净退出,而非让未捕获异常 traceback 崩溃;控制权在调用方手里。

### Q3
应**只包每轮内部的调用**。本质区别在控制流: 
- 包整个 while:某轮异常冒泡出循环体 → 整个循环终止、程序结束,后续轮次不再执行。
- 包每轮内部:异常在轮内被 except 消化 → 本轮正常收尾 → while 继续下一轮,单轮失败不拖垮整体。
"定位精度"是次要差异,核心是"失败后循环能否继续"。实践可两层:轮内细粒度捕获保活,外层再兜底非预期错误。
