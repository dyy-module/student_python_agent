## Q1（当日·概念）实例属性 vs 类属性

实例属性和类属性有什么本质区别？它分别对应 JS/TS 里的什么？什么场景你该用类属性而不是实例属性（举一个具体用途）？

- 考点：共享 vs 各实例一份；`static` 字段的迁移 + 类属性的实际用途（如所有对象共用一份校验名单/计数器）
- 我的回答：
实例属性每个实例是独立的，是在实例的时候才会初始化。 类属性是所有实例共用的，在创建类的时候就初始化了。
类实例计数器、类名称、公共属性都应该用类属性。 实例属性，比如水果类->橘子的颜色，香蕉的颜色，用实例属性

> 参考要点（对答案用，2026-10-27）：
> - **本质区别**：类属性挂在类对象上，所有实例共用一份，定义类时就创建；实例属性挂在各实例上（`self.xxx=` 那一刻诞生），每个实例各一份。读取顺序：先实例、没有再退到类。
> - **陷阱（day20 Q3 同源，你后来亲口答对过）**：`实例.类属性 = 新值` 不是改类属性，是在实例上新建同名属性遮蔽它；可变类属性 `append` 则所有实例跟着变（串号 bug 的根源）。
> - **JS/TS 对应**：类属性 ≈ `static` 字段；实例属性 ≈ 构造函数里 `this.xxx=`。
> - **场景判定一句话**：这个数据描述"这类东西"（全体共享：校验名单/计数器/默认值）→ 类属性；描述"这个"（各实例不同）→ 实例属性。你的橘子/香蕉例子对，但表述绕了——若橘子/香蕉是 Fruit 的**实例**，颜色就该是实例属性；若想做成子类，那是另一种设计（子类覆盖类属性），别和实例属性混着说。"类名称"这条建议从名单里去掉——类自己的名字是内置属性（`类.__name__`），不是手写类属性的用例。

## Q2（当日·无 JS 对应，必背）`self` 到底是什么

Python 里没有 `new` 关键字、实例方法第一个参数必须显式写 `self`，但调用时又不用传。请解释：`self` 的值是什么时候、由谁绑定的？这和 JS 的 `this`（隐式、由调用方式决定）有什么本质不同？
 
- 考点：JS 真空区；显式 self vs 隐式 this 的绑定机制
- 我的回答：
self 本质上是一个参数，实例化或者实例调用方法的时候，python 会主动把实例本身传入方法第一个参数。之所以叫self 是公约，方便其他人理解，也可以叫this,一样能运行。
js 的 this不同，this是动态的，是运行的时候赛进去的。

> 参考要点（对答案用，2026-10-27）：
> - **绑定精确到两拍**：定义 `BankAccount.deposit` 时首参只是形参名；调用 `实例.deposit(50)` 时，Python 把它转成 `BankAccount.deposit(实例, 50)`——实例作为第一个实参**在调用那一刻传入**，然后绑定到形参 self 上。谁调用，谁就被塞进第一位。
> - **措辞订正**：self 不是"参数值"，它就是首参的名字；换成 this/ctx 完全等价，只是 PEP8 约定。你说的"叫 this 一样能运行"对，且正因如此 `self.xxx=` 里的 self 只是普通形参引用，没有任何魔法。
> - **与 JS this 的本质差**：Python 的 self 是**显式形参**，写法即真相——`obj.m()` 与 `m = obj.m; m()` 报错方式一眼可预测；JS 的 this 是**执行上下文隐式绑定**，由调用形式决定（方法调用/独立调用/bind/箭头函数各不同），找不到丢失原因得追调用栈。你答出"运行时塞"是对的（原文"赛进去"应为"塞"），再补一句归属：Python 塞的位置写在签名里，JS 塞的位置藏在调用方式里——这才是面试要的对比点。
> - **无 new 的分工**：`BankAccount(...)` 先由 `__new__` 造实例（不用你写），造好立刻把实例塞进 `__init__` 的 self 完成初始化——"没有 new"只是 new 被语法糖藏进了调用括号里。

## Q3（当日·易错）`type()` vs `isinstance()`

`type(obj) is BankAccount` 和 `isinstance(obj, BankAccount)` 什么时候结果会不一样？判断"这个对象是不是某类**或它的子类**"时，为什么应该优先用 `isinstance()`？

- 考点：精确类型 vs 含子类的类型判断（day15/day16 高频追问）
- 我的回答：
1.当obj 是 BankAccount 的实例 type 和 isinstance 结果一致为true
2.当obj 不是 BankAccount 的实例且都不是 BankAccount 子类实例时，结果一致，都为false

因为 type 是直接对比，不能对比继承链上的类，而isinstance 是可以对比继承链上的类

> 参考要点（对答案用，2026-10-27）：
> - **题干问"什么时候不一样"，你两种"一样"的情况答得都对，但漏答了那个"不一样"的核心案例**：obj 是 BankAccount **子类**实例时——`type(obj) is BankAccount` 为 **False**（type 返回精确类型，是子类自己），`isinstance(obj, BankAccount)` 为 **True**（沿继承链向上逐层查，命中即真）。答题要先正面接住问句。
> - **为什么优先 isinstance**："是不是某类**或它的子类**"= is-a 关系判断，正是多态的身份语义（day16 继承后大量用）；type 判的是"是不是恰好这个类"，子类会被误拒。补一句才完整：type 真正的适用场景是取精确类型打印/调试，或刻意排除子类时。
> - **措辞微订**："type 是直接对比"——准确说是比对**精确类型**（它不是"不能对比"，是"只肯一对一比"）；isinstance 的第二参还可接元组 `isinstance(x, (A, B))`，type 无此用法。
