## Q1(当日新知·"为什么"文字题)except 顺序与 else/finally

1. 一个 try 后跟多个 except,为什么要"从具体到宽泛"(先 `FileNotFoundError` 后 `Exception`)?若先写 `except Exception:` 再写 `except FileNotFoundError:`,后者会怎样、为什么?
2. `else` 和 `finally` 都常在收尾,触发时机差在哪?哪种"只有成功才执行"的逻辑该放 else 而不是塞进 try?

- 我的回答：
- 1. 因为except 匹配到第一个错误就会停止。如果先写宽泛的父类，所有错误匹配到父类就会停止，子类分支就是无效代码，永远也走不进去。既先写Exception，永远无法匹配到FileNotFoundError
- 2. 先执行try 内容，如果没有错误， else先执行，finally 永远在最后执行。 else 只有成功才会执行，操作读取try 执行内容 等

```python
def divide(x, y):
    try:
        r = x / y
    except ZeroDivisionError:
        print("除零")
    except TypeError:
        print("类型错")
    else:
        print("结果", r)
    finally:
        print("收尾")

divide(2, 1)
divide(2, 0)

print("主程序还在")
```

# 参考答案要点(2026-10-24 对答案后沉入;本人已闭卷作答,不破坏盲写口径)

## Q1 标准答案

**1. 为何"从具体到宽泛"?**
- except 匹配是**自上而下逐个比对,命中第一个即进该分支,其余分支不再比对**。
- 先写 `except Exception:` 时,FileNotFoundError 本身就是 Exception 的子类,任何异常都会在父类分支被接住 → 后面的 `except FileNotFoundError:` 成**死代码,永远走不到**(不报错,但静默失效,更难发现)。
- 口诀:子类在前、父类在后;兜底的 `except Exception` 永远写最后。
- 反向案例(助教 2026-10-24 误判登记,非学习者错误):曾报称 input_amt 里 `except ValueError` 在 `except NegativeAmountError` 前会截胡负数——实测证伪,学习者产物一直是"子类在前"的正确顺序;教训:对照实验的变体不得当成文件现状报修(已同步登记教程侧呆账)。正确用法示例见本产物 input_amt:负数走 NegativeAmountError 精细信息,非数字走 ValueError 兜底,各得其所。

**2. else 与 finally 的触发时机差?**
- `else`:**仅当 try 块一行都没抛异常**才执行,位置在 try/except 之后、finally 之前;若 try 里 return 了,else 被跳过(C# try/finally 无此对应,JS 完全没有 else)。
- `finally`:**无论如何最后必执行**(包括 try/except 里 return 之后才走)→ 常放收尾清理;在 17 周路线里它对应第05周起"API 连接/流必须关闭"的底座。
- 只该在成功时做的事放 else,不塞 try:典型是**"依赖 try 产物、且失败时绝不能做"**的动作——读取成功后才回读内容(day19 的 else 二次打开就是此例)、写入成功后才提交计数。塞进 try 的害处:把成功后的代码也罩进保护圈,它自己抛的错会被误当"主操作失败"处理。

## Q3 标准答案

1. **day16 的什么机制**:继承。`class EmptyFileError(Exception)` 自动获得父类全部方法,自己 `pass` 也不缺能力。
2. **为什么不写 `__init__` 也带得出信息**(完整链条):
   - 子类未定义 `__init__` → 调用时**沿继承链落到父类 `Exception.__init__`**(注意:不是"被隐藏",是 MRO 向上查找——你 day16 学的属性查找顺序);
   - `Exception.__init__` 把 raise 时的参数存进 **`self.args`**;
   - 打印/str() 时触发 `Exception.__str__`,默认把 args 格式化成文本;
   - 实测分界:`str(ValueError())` 是**空串 ''**——不带参数就没信息;`str(ValueError('x'))` → 'x'。
3. **本日产物的实际做法**:EmptyFileError 重写了 `__str__` 固定返回"文件不能为空"——所以那句提示是**自定义的**,不是 Exception 自带的;NegativeAmountError 则走了"带参 raise + 继承 __str__"的默认链路("金额不能小于0,输入金额为-5.0")。两条路都合法,面试能说清差别即加分。
