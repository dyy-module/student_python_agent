## Q1（当日新知·概念）`__str__` vs `__repr__`

`print(obj)` 和在解释器里直接敲 `obj`，触发的分别是哪个魔术方法？两者定位区别是什么？为什么廖雪峰说"通常两者代码一样"时可以写 `__repr__ = __str__` 这一行偷懒？

- 考点：dunder 触发时机 + "面向用户 / 面向调试"的定位差异
- 我的回答：
- print 触发的时 __str__ 方法,直接敲触发是__repr__方法。
- print/str/f"{obj}" 统一触发__str__， repr(obj)/f"{obj!r}"/print([obj, obj]) 触发__repr__
- __str__ 定位是面向用户的，用于输入内容，可读，好看就行。
- __repr__ 是面向开发者用于调试的，无歧义，理想是“能还原对象”的合法表达式
- 为什么 可以写 `__repr__ = __str__`。机制：它只是普通的“起别名”，类体就是一个普通命名空间，def 的本质是“把函数对象绑定到名字上”。
 
 ```python
	class A:
	    def __str__(self):
	        return 'hi'
	    __repr__ = __str__          # 把 __repr__ 这个名字也绑到同一个函数对象上
	A.__repr__ is A.__str__         # True —— 同一个对象，没有拷贝、没有包装

 ```
 如果功能一致，此时一行别名是最干净的去重，而不是偷懒出错。

## Q2（往期复习·无 JS 对应，面试高频）`self` 与继承构造

（a）Python 每个实例方法为什么必须把 `self` 显式写成第一个参数？这和 JS 的 `this` 有什么本质区别（提示：谁决定 this/self 的绑定）？
（b）子类重写了 `__init__` 却忘了先调 `super().__init__(...)`，最典型的后果是什么？

- 考点：JS 真空区必背差异 + day16 最易报错点
- 我的回答： 
- a:self 之所以必须显式写出来，是因为 Python 的方法调用没有魔法接收者：obj.m(...) 被翻译成 M.m(obj, ...)，那个被自动塞进去的实例必须有一个形参来接住它。这套设计用一点点样板代码，换来了函数与方法之间的无缝统一、属性来源的清晰可读，以及零特殊作用域规则——这正是 Python “简单一致胜过语法糖”的典型取舍。
- b:self 是一个真实的局部变量（形参），在“访问属性”那一刻由描述符协议把实例填进去；this 是一个关键字，在“调用”那一刻由调用方式动态决定，跟函数定义在哪无关。

## Q3（往期复习·代码·阅读说输出）类属性 vs 实例属性

下面代码两行 `print` 各输出什么？为什么 `c1.total` 在实例自己没有该属性时也能打印出来？为什么 `c1.total = 100` 之后 `Counter.total` 却没跟着变？

```python
class Counter:
    total = 0                     # 类属性
    def __init__(self):
        Counter.total += 1

c1 = Counter()
c2 = Counter()
print(c1.total, c2.total, Counter.total)   # 行A
c1.total = 100
print(c1.total, c2.total, Counter.total)   # 行B
```

- 考点：属性查找顺序（实例→类）+ 实例属性"遮蔽"类属性（day15 类属性陷阱家族）
- 我的回答：(闭卷原答正确,以下为标准回答)

**行A → `2 2 2`**:`total = 0` 是类属性;两次 `Counter()` 各执行 `Counter.total += 1`(经**类名**修改,全局生效)→ 类属性变 2。`c1`/`c2` 自身没有 `total`,读属性时沿「实例 → 类」上溯,都拿到类的 2。

**行B → `100 2 2`**:`c1.total = 100` 是**赋值**,赋值永远写在**实例 `c1`** 上——给 c1 新建了一个实例属性 `total`。
- `c1.total` → 实例先命中 → 100
- `c2.total` → c2 无实例 total → 回落类 → 2
- `Counter.total` → 类属性从未被这次赋值改动 → 2

**为什么说“遮蔽”而不是“覆盖”**:类属性本身没被改(仍是 2),只是**读取时实例属性优先级高于同名类属性**,把它挡住了(shadow)。

**一句话机制**:属性**读 = 双向查找(实例优先、找不到再上溯到类)**;**写 = 只落实例**。这一“读写不对称”就是全部机关。

**高频追问(加分)**:
1. 想让赋值影响所有实例 → 经类名改 `Counter.total = 100`(这也是 `__init__` 用 `Counter.total += 1` 而非 `self.total += 1` 的原因)。
2. `self.total += 1` 在 `__init__` 里的后果 → 先读类值、再写回实例,该实例从此与类属性分家,计数器不再全局共享(经典陷阱)。
3. 取消遮蔽 → `del c1.total`,c1 重新回落到类属性 2。
