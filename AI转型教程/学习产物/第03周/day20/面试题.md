## Q1(当日·"为什么"文字题)手写序列化与读盘容错

1. 你的 to_line/from_line 为什么能替代 json?如果某天 json 解禁了,手写序列化还有什么保留价值?
2. 读盘时遇到一条坏行,三种可选处置:整程序崩溃 / 跳过并警告 / 跳过但静默——你为什么选现在这种?生产级 AI 服务加载数据集时,这条口径要不要变?

- 我的回答:
  1. **为什么能替代 json**：数据是单层扁平结构(日期/描述/状态 三字段逗号分隔)，不需要 json 的嵌套/类型系统；格式由类自身定义(to_line 写、from_line 读)，等于自定义协议，天然可控。**json 解禁后手写仍有的保留价值**：①学习价值——理解序列化本质而非调 API；②格式自由——可以选 csv/竖线分隔/定宽，适配旧系统；③无依赖——部署不需要装库，嵌入式/面试白板场景可直接跑。
  2. **为什么选"跳过+警告"**：崩溃=一条脏数据毁掉全部有效数据，太脆弱；静默=数据悄悄丢了你不知道，太危险。跳过+警告是可用性与可观测性的折中——程序继续、用户知情。**生产级 AI 服务要不要变**：要。训练数据集的完整性直接决定模型质量，这里不能"悄悄丢样本"；应改为 fail-fast(崩)+把坏行隔离到单独文件供人工复查，或至少聚合计数+告警阈值(超过 1% 拒绝整个数据集)。业务缓存可以容忍少量丢失，但训练数据不行。


## Q2(当日·阅读说输出)try/else/finally + 函数 return

下面 `load` 被调用两次,请逐次说出打印哪几行、main 里 n 等于多少、程序是否崩溃(注意 return 与 finally 的先后):

```python
def load(path):
    try:
        f = open(path, "r", encoding="utf-8")
    except FileNotFoundError:
        print("没找到,用空的")
        return []
    else:
        print("打开了")
        f.close()
        return ["a,b"]
    finally:
        print("收尾")

n = len(load("no_such_day20_file.txt"))
print("n =", n)
```

- 我的回答:
- load 的文件不存在，所以触发FileNotFoundError 打印：没找到,用空的， 返回[],执行finally，打印收尾。然后 n= len([]) 既0，打印 n=0

  **参考要点·逐题对答**(题目说"调用两次"但代码只给了一次不存在的调用——面试时遇到这种不一致要主动说"我分两个场景各答一遍"):
  - **场景1 文件不存在**(当前代码):
    - 打印顺序:`没找到,用空的` → `收尾` → `n = 0`;不崩
    - 关键机制:except 里 `return []` 被"排队"，但 finally **一定在 return 真正生效之前执行**——这是 finally 的核心保证(即使函数要退出也扫尾)。很多人会误答成先 return 后 finally。
    - else 块不执行(有异常)
  - **场景2 文件存在**:
    - 打印顺序:`打开了` → `收尾` → `n = 1`;不崩
    - try 无异常 → 走 else 分支 → 排队 `return ["a,b"]` → finally `收尾` → 真正返回长度为 1 的列表
  - **面试可延回的一句本质**:try/except/else/finally 里 `finally` 是唯一块——无论异常、无论 return、甚至未处理异常向上抛都会执行，以它做资源释放/日志扫尾最可靠(但 `sys.exit`/断电 等极端情况仍会跳过)。


## Q3(往期复习·隔期主动回忆)类属性 vs 实例属性

day15 的 bank_account 用类属性放 bank_name、实例属性放余额。现在改成学生场景:如果 score 误写成了类属性(所有学生共享一份),增删查会出什么具体症状?一句话说明类属性和实例属性各自的"归属"。(出处:廖雪峰 10.5)

- 我的回答:
```python
class Student:
    score =12
    def __init__(self,name,score):
        self.name =name
        self.score =score

s1 = Student('a','24')
这种复写了 score 的情况，访问 print(s1.score) // 24,不影响实例访问
但是访问Student.score 则为12
```

  **参考要点·逐题对答**(你答对了"遮蔽"机制，但题目真正问的是"症状"与"归属一句话"，面试时这两块必须直接命中):
  - **增删查具体症状**(你未展开，面试时逐条列):
    - 新增:`Student('A')` 未显式 `self.score = score` 时，`s1.score` 读到共享的 12;A/B/C 三人看起来成绩一样，数据串号
    - 修改:`s1.score = 90` 实际给 s1 新建了一个实例属性(遮蔽了类属性)，s2.score 仍读到 12——表面"改一个不动另一个"、其实两个名字指向不同的东西
    - 列表推导统计均分:`sum(s.score for s in students)` 把“仅被显式写过的实例”与“未写的实例”混在一起算，均分不可预期
    - 删掉 s1:`Student.score` 仍在类上，下次新建实例又拿到老默认值——看起来"删不干净"
    - 极端坑:__init__ 里写 `self.score = self.score + 1` 会先读类属性、再写实例属性，不同实例行为不一致
  - **归属一句话**:**类属性 = 类本身拥有、所有实例共享**(适合常量/白名单/跨实例计数);**实例属性 = 单个对象拥有、只活在 self 上**(每个对象独立)。实例可读类属性，但写入时默认在实例上新建同名属性而非修改类属性。
  - **小 bug 提醒**:`self.name = name,` 行末多了个逗号——Python 会把它当 `(name,)` 元组，不是字符串。面试时手写代码要格外注意(单元素元组陷阱)。
