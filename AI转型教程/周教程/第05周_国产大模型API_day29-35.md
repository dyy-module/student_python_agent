### 讲解

结论先行:选型看三点——中文文档是否完善、是否有免费/低成本档、SDK 是否 OpenAI 兼容(兼容则一套代码可切换多家端点)。今天先用 dict 把三家信息结构化打印,再用 try/except 探测 SDK 是否已在 venv 内装好。整个文件不联网、不需要 key,把"环境就绪"和"安全规矩"先立住。路径处理用 pathlib:Path.cwd() 拿当前目录,Path(...) / "output" 用 / 拼子路径,mkdir(parents=True, exist_ok=True) 目录已存在也不报错(幂等),write_text() 一步完成打开-写入-关闭(记得 encoding="utf-8")。下面代码块为教学演示,非产物答案。

```python
# 命令行(venv 内)先安装: pip install openai   再写入 requirements.txt
models = {
    "DeepSeek": {"优势": "性价比高/中文强", "免费档": "有试用额度"},
    "通义千问": {"优势": "阿里云生态/Qwen 系列", "免费档": "有免费档"},
    "智谱GLM": {"优势": "国产自研/工具链全", "免费档": "有免费额度"},
}
try:
    import openai                       # 大模型 SDK(第三方库,Day22 已解禁)
    print("SDK 已安装,版本:", openai.__version__)
except ImportError:
    print("未检测到 SDK,请先在 venv 内执行 pip install")
for name, info in models.items():       # 遍历打印选型对比
    print(f"{name}: {info['优势']} | {info['免费档']}")
from pathlib import Path                # 路径处理(今日首教):定位/建目录/落盘
out_dir = Path.cwd() / "output"         # / 拼接子路径
out_dir.mkdir(parents=True, exist_ok=True)  # 幂等建目录:已存在不报错
print("对比表将落盘:", out_dir / "model_compare.txt")  # write_text 由你在产物实现
```

## Day31(周三,7h)· Chat API 进阶:多轮上下文 / system prompt / 参数

今天让对话"有记忆、有人设、可调风格"。核心是理解 messages 数组就是对话上下文:把 system(定角色)、历次 user、历次 assistant 依次累积进去,模型才记得前文。再学会用 temperature 等参数调节输出。产出:multi_turn_chat.py,一个能连续追问的命令行单轮-多轮对话脚本。

💡 JS开发者速读:messages 数组 ≈ 你在前端维护的"聊天记录 state",每次请求把整段历史带上;system prompt ≈ 给组件预设的 props/配置;temperature ≈ 一个调节"随机度"的参数,类似你控制动画随机抖动的幅度。

### 学习内容

- messages 三种 role:system(定角色/规则)、user(用户输入)、assistant(模型回复)
- 多轮上下文:把每轮 user 与 assistant 消息 append 回 messages 列表再请求
- system prompt 写法:设定身份、语气、输出约束
- 关键参数:temperature(随机度)、max_tokens(长度上限)的作用与取值直觉
- while + input + break 驱动多轮交互(第01/03周控制流复用)

### 讲解

结论先行:大模型本身无状态,"记忆"完全靠你每次把完整 messages 历史带上去。system 放最前定人设,之后 user/assistant 交替 append。temperature 越低越确定(适合事实/结构化任务),越高越发散(适合创意)。多轮循环就是 input→append user→请求→append assistant→打印,直到用户输入退出词 break。下面代码块为教学演示,非产物答案。

```python
# client 沿用 Day30 演示的初始化(key 从环境变量读 + base_url 指向国产端点)
messages = [
    {"role": "system", "content": "你是简洁的 Python 助教,回答不超过两句"},
    {"role": "user", "content": "什么是列表?"},
]
resp = client.chat.completions.create(
    model="deepseek-flash",
    messages=messages,
    temperature=0.7,               # 越低越确定,越高越发散(flash 会忽略此值,见教材段参数现实口径)
    max_tokens=200,                # 长度上限;设小可观察截断(finish_reason=length)
)
answer = resp.choices[0].message.content
messages.append({"role": "assistant", "content": answer})   # 累积上下文
messages.append({"role": "user", "content": "那元组呢?"})    # 追问,模型记得前文
```

## Day32(周四,7h)· Prompt 工程基础:角色 / 指令 / 少样本 / 思维链认知

今天从"能调用"升级到"会指挥"。同样一个模型,Prompt 写得好不好,输出质量天差地别——这是 AI 应用岗的核心软实力。你要掌握角色设定、清晰指令、少样本(few-shot)三大利器,并对思维链(chain-of-thought)建立认知。产出:prompt_basic.py,用"无技巧 vs 有技巧"对比证明 Prompt 的价值。

💡 JS开发者速读:Prompt 工程 ≈ 你给下游服务/组件写"清晰的接口契约 + 示例数据";少样本 ≈ 在需求里塞几个 example 让实现方照做;角色设定 ≈ 给函数传入的配置项;思维链 ≈ 让程序"打印中间步骤"再给结果,便于校验。

### 学习内容

- 角色设定(system):给模型一个身份,约束语气与专业度
- 清晰指令:明确任务、输出格式、长度、语言边界(可测量的约束)
- 少样本 few-shot:在 messages 里塞入若干"输入→期望输出"示例对
- 思维链认知:让模型"一步步思考"再给结论(认知级,本周不深入其变体)
- 用 def 封装"发一次请求"以复用(第02周函数复用)

### 讲解

结论先行:好 Prompt = 角色 + 清晰指令 + 必要示例。少样本最实用的落地方式,就是在 messages 里插入几组 user/assistant 示例对,模型会模仿其格式与风格。今天用同一任务跑"裸 prompt"和"角色+指令+少样本"两版,直接对比输出质量差异,把 Prompt 的价值"眼见为实"。下面代码块为教学演示,非产物答案。

```python
system_prompt = "你是电商文案专家,只输出简体中文,每条不超过 20 字。"
few_shot = [                              # 少样本:塞入示例对
    {"role": "user", "content": "商品:保温杯"},
    {"role": "assistant", "content": "锁温 12 小时,一杯暖一整天。"},
]
user_prompt = "商品:机械键盘"
messages = [{"role": "system", "content": system_prompt}] + few_shot \
           + [{"role": "user", "content": user_prompt}]
# 之后用封装好的 ask(messages) 发一次请求并打印
```

## Day33(周五,7h)· 结构化输出:JSON Mode 让模型稳定返回可解析 JSON

今天解决工程化最关键的一环:让模型输出"程序能直接吃"的结构化数据。自由文本难以解析,JSON Mode(response_format=json_object)能强制模型返回合法 JSON,再用 json.loads 转成 dict 供后续逻辑使用。这是第07周 RAG、第12周生成式 UI、项目2"自然语言→JSON Schema"的直接地基。产出:json_output.py。

💡 JS开发者速读:JSON Mode ≈ 你给 axios/fetch 设 `responseType: 'json'`,约定后端必返合法 JSON;`json.loads` ≈ `JSON.parse`,`json.dumps` ≈ `JSON.stringify`;从 dict 取字段 ≈ 访问对象属性。你十年的前后端 JSON 契约经验在这里完全复用。

### 学习内容

- 开启 JSON Mode:请求参数 response_format={"type":"json_object"}
- 在 Prompt 里明确要求返回哪些字段(schema 认知,用自然语言描述)
- 用 json.loads 把返回字符串解析为 dict,并按 key 取字段
- 解析健壮性:try/except 处理 json.loads 失败(JSONDecodeError)
- 对比"未开 JSON Mode"与"开 JSON Mode"两次输出的可解析性

### 讲解

结论先行:开 JSON Mode 只需在 create 里加 `response_format={"type":"json_object"}`,并在 Prompt 里说清要哪些字段;返回的是 JSON 字符串,用 `json.loads` 转成 dict 即可按字段取值。务必用 try/except 兜住解析失败——即便开了 JSON Mode,字段是否符合预期仍需校验。下面代码块为教学演示,非产物答案。

```python
import json
resp = client.chat.completions.create(
    model="deepseek-flash",
    messages=[{"role": "user",
               "content": "分析情感,返回JSON含字段label和score:客服态度很好"}],
    response_format={"type": "json_object"},   # 开启 JSON Mode
)  
raw = resp.choices[0].message.content
try:
    data = json.loads(raw)                      # 字符串 → dict(≈ JSON.parse)
    print("情感:", data["label"], "分值:", data["score"])
except json.JSONDecodeError as e:               # 解析失败兜底
    print("JSON 解析失败:", e, "原始:", raw)
```
