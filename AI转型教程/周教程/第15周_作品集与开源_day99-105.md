## Day100(周二,7h)· RAG 问答链路开发:检索 + 生成 + 引用

按昨日蓝图,今天把后端最核心的一段做成真模块:商品语料入库(切分/向量化)、按问题检索 topK、拼 context 并约束"仅根据资料回答"、流式生成、来源随片段跟随。这是旗舰的技术心脏,也是面试必问的"你的 RAG 怎么保证不瞎编"的答案本体。产出:后端 RAG 问答模块(可被接口层调用)。

💡 面试官视角速读:"RAG 幻觉怎么治?"——三件套:①提示约束"仅根据资料回答,没有就说不知道";②引用来源(每句结论可回溯);③检索为空兜底(不硬答)。今天把这三件做进链路,面试就不再靠嘴说,而是指代码。另备好"为什么这么切分/为什么 topK=K"的调参理由,那是周08评测思想的延续。

### 学习内容

- 语料入库流水线:加载→切分(chunk_size/overlap 复用周07调参结论)→向量化→入库
- 检索 topK 与"来源跟随":每个片段自带来源元数据,供引用与前端展示
- context 拼接与提示约束:仅根据资料回答/无资料明确说不知道/结论附来源
- 流式生成器:把 LLM 流式输出包装为可被接口层逐块消费的异步生成器(接口明天接)
- 检索为空/低相似度时的兜底策略

### 讲解

结论先行:RAG 链路的工程质量体现在"来源信息从检索阶段就跟着片段走"。切分时给每个片段登记来源,检索命中的 topK 就自带出处;生成阶段把"资料+来源编号"一起拼进提示,模型输出才能"自带引用"。流式生成器设计成异步生成器,接口层只管逐块消费——分层解耦,明天换接口实现不动它。

```
RAG 问答链路 · 数据流示意(教学演示,非产物答案)
用户问题 q
  → 向量检索 topK=4 ──▶ [(片段, 来源, 距离), ...]
  → 拼 context:"资料1[来源:商品A-FAQ] ..."
  → 提示约束:"仅根据资料回答;每条结论后附[来源n];资料中没有就说不知道"
  → LLM 流式生成 ──▶ 逐块 yield 给接口层
关键:来源在切分/入库时就绑定到片段,引用才"随检索自然产生"
```

## Day101(周三,7h)· FastAPI 流式问答接口(SSE)

昨天有了 RAG 模块,今天把它暴露成标准 SSE 流式接口:前端 POST 一个问题,服务端持续推送 `data: ...\n\n` 分帧,并把引用来源与结束/异常信号也纳入协议。同时补齐工程件:Pydantic 请求模型、CORS、异常与超时、.env.example(不含真实 key)。产出:可本地联调的 /chat 流式接口。

💡 面试官视角速读:面试官爱问"SSE 帧格式是什么?半包怎么处理?和 WebSocket 怎么选?"——周10你在前端消费过流,今天从服务端视角补全另一半:分帧规则、流式响应、断连与超时。能前后端两面都讲清的人极少,这正是"前端×LLM 交互层"定位的护城河时刻。

### 学习内容

- Pydantic 请求模型(校验问题非空/长度)与响应约定
- SSE 帧格式:`data: <内容>\n\n`;自定义事件承载来源与结束信号
- StreamingResponse + async 生成器:把 day100 的生成器逐块推给客户端
- 工程健壮性:异常不崩(捕获后发错误帧并收尾)、客户端断连处理、超时
- CORS 配置与 .env.example(仅键名,不含真实 key)

### 讲解

结论先行:FastAPI 里做 SSE 的标准姿势是"路由返回 StreamingResponse,内容来自一个 async 生成器"。生成器内部调 day100 的 RAG 链路,把每个生成块包成 SSE 帧 `data: ...\n\n` yield 出去;引用与结束信号用自定义帧承载。注意两点:①key 只从环境变量读;②客户端中途断开时生成器要能被正确终止(释放资源)。

```python
# FastAPI 流式接口 · 骨架示意(教学演示,非产物答案)
from fastapi import FastAPI
from fastapi.responses import StreamingResponse

app = FastAPI()

@app.post("/chat")
async def chat(req: ChatRequest):            # ChatRequest:Pydantic 请求模型(周13已学)
    async def gen():
        async for chunk in rag_stream(req.question):   # day100 的 RAG 生成器
            yield f"data: {chunk}\n\n"                 # SSE 帧:以空行结尾
        yield "event: done\ndata: [DONE]\n\n"          # 自定义结束帧
    return StreamingResponse(gen(), media_type="text/event-stream")
```

💡 面试官视角速读:这就是"前端×LLM 交互层"差异化的落地实锤——现场演示"提问→逐字浮现→Markdown 排版→来源角标→点停止立刻断"的完整链路,胜过简历上十行描述。面试加分点:你能讲清"半包处理"(SSE 帧被 TCP 分块切开时如何缓冲拼接),这是从"能用"到"工程可靠"的分水岭。

### 学习内容

- fetch + ReadableStream 消费 POST SSE 流:帧缓冲与半包处理(按 `\n\n` 切帧,残帧留缓冲)
- 消息状态接入:分块累积进当前 AI 消息(复用周10 useStreamChat 心智)
- 引用来源渲染:把服务端来源帧渲染为角标/来源卡(可展开)
- 中断按钮接 AbortController(周10),中断后界面状态正确复位
- 加载态/错误态/空态处理;TS 类型完整(消息/帧/来源)

### 讲解

结论先行:前端接 POST SSE 的要点是"缓冲 + 切帧"。网络分块与服务端帧边界不对齐(半包),所以必须把到达字节累积进 buffer,按帧分隔符 `\n\n` 切分,切不完整的留在缓冲等下一块。解析出的 data 帧累积进当前 AI 消息,event 帧分别处理来源与结束。这套逻辑你在周10 已写过雏形,今天接真接口并加上来源渲染与错误态。

```tsx
// 前端消费 SSE 流 · 半包处理示意(教学演示,非产物答案)
const res = await fetch("/api/chat", { method: "POST", body: JSON.stringify({ q }) });
const reader = res.body!.getReader();
const decoder = new TextDecoder();
let buf = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buf += decoder.decode(value, { stream: true });     // 累积,处理半包
  const frames = buf.split("\n\n");                    // 按帧分隔切分
  buf = frames.pop() ?? "";                            // 残帧留缓冲
  for (const f of frames) { /* 解析 data:/event: 帧 → 更新消息或来源 */ }
}
```

2. 可访问性:公网 HTTPS URL 现场打开可玩;或本地 `docker compose up` 一条命令起全链路。
3. README 五项核对:架构图/成本数据(真实)/真实数据说明(非 mock)/在线 URL/技术选型说明,逐项勾。

量化通过线(4 维评分,项目级口径):

| 维度 | 通过 | 部分通过 | 未通过 |
| ---- | ---- | ---- | ---- |
| 功能完整 | 闭环 4 步(提问/检索/生成/流式展示)全通,3 问回答合理且带引用 | 闭环通但 1 问不合理或引用缺失 | 闭环跑不通 |
| 工程规范 | 公网 HTTPS 可访问或一键起;key 全环境变量;结构清晰;断连/异常不崩 | 可访问但需手动多步,或个别规范项缺失 | 无法部署或 key 硬编码 |
| 文档质量 | README 五项齐全且数据真实可核 | 缺 1 项或个别数据口径不全 | 缺 ≥2 项或数据虚构 |
| 业务价值 | 绑定电商商品/营销域,能讲清"懂业务能交付"叙事 | 与业务域相关但叙事弱 | 通用 demo,无业务域绑定 |

结论口径:四维全部"通过"= 通过;出现"部分通过"= 部分通过(下周前 2 天补齐对应项后复验);出现任一"未通过"或闭环跑不通 = 未通过(定位对应 day 重做,闸门顺延不取消)。

未通过补救方案:

- 个别环节断裂(如某一个问题回答不佳)→ 当天缓冲 1h 定位订正(多为检索参数或语料覆盖),次日复验该问题;
- 链路不通或部署失败 → 重做对应 day(day100 检索/day101 接口/day102 前端/day103 部署),再约复验;
- 文档缺项 → 按 README 验收清单逐项补齐,数据必须真实(严禁为凑数虚构,诚信优先);
- 整体严重拖延(>90min 仍未跑通演示)→ 本周降级:第16周前 2 天先补 MVP 欠账,打磨与差异化项目顺延,闸门顺延但不取消。
