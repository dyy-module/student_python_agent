## Day15(周一,7h)· OOP入门:class / __init__ / self

今天正式进入面向对象。你已完成extra跟练,固定产物 bank_account.py 还没写——今天把它补齐。OOP对你不陌生:JS的class你已用了十年,重点是搞清Python与JS的差异(显式self、__init__而非constructor、无真正私有)。产出:一个可存取款、可查询的银行账户类。

### 讲解

结论先行:Python里"类"是模板,"实例"是按模板造出的对象;所有实例方法都必须把实例自身作为第一个显式参数self传入(调用时Python自动传,定义时必须写)。类属性属于类本身(所有实例共享),实例属性每个实例各自一份——与JS的static字段vs实例字段同构。

第二个结论:type(obj) 返回对象的类(≈JS typeof,但更精确);isinstance(obj, X) 返回bool,判断 obj 是否是 X **或X的子类**的实例(≈JS instanceof)。两者差异只在继承:isinstance() 认子类是父类类型,type() 不认。因此本项目里"判断某对象是不是 BankAccount 实例"应优先用 isinstance()——具体怎么写由你完成。

```python
# 教学演示,非产物答案(BankAccount 的存款/取款/展示方法请自行盲写)
class BankAccount:
    bank_name = "杭州银行"          # 类属性,所有实例共享(≈ JS static)

    def __init__(self, owner, balance=0.0):   # ≈ JS constructor
        self.owner = owner          # 实例属性(≈ this.owner)
        self.balance = balance

    def deposit(self, amount):      # 实例方法首参必须是 self
        self.balance += amount
        return self.balance

type("abc")                       # <class 'str'>  → JS typeof
isinstance(3.14, float)           # True          → JS instanceof
isinstance("3.14", int)           # False
isinstance("3.14", (int, float))  # False;传元组=满足其一即True
```

## Day16(周二,7h)· 继承 / 方法重写 / super() / 多态

今天学"复用与扩展"。让一个类继承另一个类,复用父逻辑再局部改写——这是JS extends的翻版,差异在于Python支持多继承、super()用法更灵活。产出:员工类继承体系,用多态统一计算不同工种薪资。

💡 JS开发者速读:class Sub extends Base → class Sub(Base);super(...) → super().__init__(...);方法重写概念完全一致。重点差异:Python用issubclass()判断类继承关系,且多继承是JS没有的能力(本周只用单继承)。

### 学习内容

- 继承语法 class Sub(Base)(JS对应extends)
- 方法重写override(JS对应子类同名方法)
- super().__init__()调用父类构造(JS对应super())
- 多态:同一接口不同实现
- issubclass()

```python
# 教学演示,非产物答案(employee.py 的类名/字段/加成规则请按「当日产出」自行盲写)
class Payment:                    # 基类
    def __init__(self, amount):
        self.amount = amount
    def fee(self):                # 父类默认实现
        return 0.0

class CardPayment(Payment):       # 继承
    def __init__(self, amount, rate):
        super().__init__(amount)  # 先让父类把它那份字段初始化,再补自己的
        self.rate = rate
    def fee(self):                # 重写:多态
        return self.amount * self.rate

for p in [Payment(100), CardPayment(100, 0.06)]:
    print(p.fee())                # 调用方不必知道 p 的确切类型
```

### 讲解

结论先行:子类自动获得父类属性和方法;需改动时用同名方法重写,需在父类逻辑上追加时用super()先调父类再补充。多态让调用方"只关心方法名,不关心具体类型"。

第三个结论(本日最可能的报错点):子类重写了 `__init__` 却不先调父类构造时,父类那份字段初始化不会发生,后续访问该字段就会报属性不存在——这是 super() 在本日的实际作用,不是可省的仪式。super() 的无参写法只在「类内方法体内」有效,写在嵌套函数里会拿不到正确的类与 self(出处见下方官方 functions#super 页)。

## Day17(周三,7h)· 魔术方法(dunder)让对象"活"起来

今天让自定义类像内置类型一样好用:能print出可读内容、能用==比较、能+相加、能len()。这就是魔术方法。JS里对应toString()、Symbol.toPrimitive、valueOf——但Python的dunder体系更统一强大。产出:二维向量类。

💡 JS开发者速读:__str__≈toString();__eq__≈自定义相等(JS无运算符重载,Python有);__add__/__len__/__lt__是JS没有的运算符重载能力,是本周重点新知。

### 学习内容

- __str__(可读字符串,print/str()触发)与__repr__(调试字符串)
- __eq__(相等比较==)
- __add__(加法+,运算符重载)
- __len__(len()触发)、__lt__(<触发,可用于排序)
- dunder方法的调用时机(由Python自动触发)

### 讲解

结论先行:魔术方法是"给Python运算符/内置函数挂钩子"。定义__add__,a+b就自动调用;定义__len__,len(obj)就自动生效。__str__面向用户(可读),__repr__面向开发者(明确、最好能重建对象)。

```python
class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __str__(self):
        return f"Vector({self.x}, {self.y})"
    def __add__(self, other):           # 支持 v1 + v2
        return Vector(self.x + other.x, self.y + other.y)
    def __eq__(self, other):            # 支持 v1 == v2
        return self.x == other.x and self.y == other.y
    def __len__(self):                  # 支持 len(v)
        return 2
```

## Day18(周四,7h)· 文件读写:open / with

今天让程序与外部世界交换数据。所有AI应用都要读文档、写日志、存结果——文件I/O是第07周RAG"文档加载"的最底层能力。重点掌握 with open(...) 上下文管理器(自动关文件,比JS手动close更安全)。产出:文本文件统计器。

💡 JS开发者速读:JS的fs.readFileSync/fs.writeFileSync心智模型可迁移,但关键差异:Python用with语句自动管理资源关闭(类似try-with-resources),JS没有直接对应;文本模式默认按行处理,encoding='utf-8'必须显式写(Windows尤其重要,否则中文乱码)。

### 学习内容

- open(path, mode, encoding)与文件模式r/w/a(读/写覆盖/追加)
- with上下文管理器(自动关闭,JS无直接对应)
- read()/readline()/readlines()三种读取方式
- write()/writelines()写入
- 逐行遍历文件对象 for line in f:(最省内存)

### 讲解

结论先行:永远用 with open(...) as f: 而不是裸open()——with保证无论是否出错文件都会被正确关闭。读写文本务必显式encoding='utf-8'。w会清空原内容,a追加到末尾,r只读(文件不存在会报错——这正是明天异常处理要解决的)。

```python
# 写(覆盖)
with open("note.txt", "w", encoding="utf-8") as f:
    f.write("第一行\n")
# 追加
with open("note.txt", "a", encoding="utf-8") as f:
    f.write("第二行\n")
# 逐行读(省内存)
with open("note.txt", "r", encoding="utf-8") as f:
    for line in f:
        print(line.strip())   # strip去掉行尾换行符
```

## Day19(周五,7h)· 异常处理全体系:try / except / raise

今天解决昨天遗留问题:文件不存在、权限不足、数据格式错误怎么办?答案是异常处理。这是生产级AI服务的命脉——API超时、限流429、JSON解析失败全靠它兜底。你已会try/catch(JS),今天重点是Python的except/else/finally、多异常捕获、raise主动抛出、自定义异常类(结合本周OOP)。产出:健壮的文件读取器。

💡 JS开发者速读:try/catch/finally心智模型直接迁移;差异——Python是except(不是catch)、可按异常类型分别捕获(JS靠if(e instanceof X)手动判断)、多了else(无异常时执行)、raise≈JS throw、自定义异常继承Exception(≈JS extends Error)。

### 学习内容

- try/except/else/finally完整结构
- 按类型捕获多种异常(FileNotFoundError/PermissionError/ValueError等)与as e取异常对象
- 异常层次:所有异常继承自Exception
- raise主动抛出异常(JS对应throw)
- 自定义异常类(继承Exception,结合Day16继承)

### 讲解

结论先行:try包裹"可能出错的代码",except按类型分别处理,else在没出错时执行,finally无论如何都执行(常用于收尾)。捕获要"从具体到宽泛",最后才兜底Exception。自定义异常就是"继承Exception的类"。

```python
class NegativeAmountError(Exception):   # 自定义异常(继承)
    pass

def load(path):
    try:
        with open(path, "r", encoding="utf-8") as f:
            return f.read()
    except FileNotFoundError:
        print(f"文件不存在: {path}")
        raise                    # 记录后可重新抛出
    except PermissionError as e:
        print(f"无权限: {e}")
    else:
        print("读取成功")
    finally:
        print("读取流程结束")
```
